## 3. Fix one — the digest published a third-party repo (#159)

### What was wrong

`utils/hiqs_digest.py` resolved the watched set in exactly **one** place — the
data-staleness report — and nowhere else. The SHIPPED / merged / commit collectors queried
`github_items`, `github_commits` and `github_direct_commits` with a **day-window predicate
only**. Any repo in the corpus, authored by anyone, reached the digest.

The ignore list governs **collection**, not **presentation**. Removing a repo from the
watchlist stops it syncing — and the operator sees `watched` drop by one, which reads like
the lever worked. Every row it already wrote stays in those tables forever.

The 2026-09-03 1705 dry run led with `deusdata/codebase-memory-mcp: Merged 7 PRs` — a repo
ignored hours earlier, **zero** operator commits ever, the seven PRs belonging to six
unrelated accounts. The same defect produced the 2026-09-01 headline "Merged 11 PRs" from
eight other people's work.

That matters because the digest is **outward-facing**: it git-pushes
`digests/hiqs-<date>-<slot>.md` into `Hypercart-Dev-Tools/rebalance-git-pulse`, and AEGIS
Sleuth's snapshot-relay polls that directory and posts to a shared Slack channel. Once
relayed it is effectively irreversible.

### What changed

- `resolve_watched_repos(db)` — the current set, canonicalized and lowercased, recomputed
  live. Raises on failure or empty.
- `_watched_predicate()` — `(sql, params)` compared against the **same** canonical
  expression the queries group by, so an org mirror stored under an old owner spelling
  still matches a repo watched under the new one (#147).
- `collect_github(db, bounds, watched)` — `watched` is a **required positional with no
  default**, deliberately. A permissive default would let the unfiltered path return the
  moment one caller omitted it.
- The day-commits CTE carries the predicate once, so `commit_total`, the commits detail
  and the `by_repo` commits branch inherit it from one site; the four `github_items`
  queries carry it explicitly.
- `build_facts()` resolves once and **fails the GitHub half closed** if it cannot.

## 4. Fix two — the memory guard killed the embeddings job 179× (#157)

### What was wrong

`obsidian-vault-embeddings` refused to start **179 times across 9 days**, 36 times in a
single day on four separate days — every scheduled run those days. Typical message:

```
refusing to start: memory compressor holds 22.9 GB, ceiling is 16.0 GB
(the machine is already under real pressure)
```

The machine was not under pressure. During a refusal: `memory_pressure` 64% free,
`vm.swapusage` 0.00M used, no paging. The job peaks at **1.86 GB** and moves the
compressor by **0.23 GB**.

`DEFAULT_MAX_COMPRESSOR_FRACTION = 0.25` was sized from 1,602 sampler rows whose
distribution was strongly bimodal — 0.65–0.96 GB healthy, 25–35 GB in distress, "almost
nothing between" — and placed at 16 GB precisely to sit in that empty middle. **The middle
is no longer empty**: this machine idles at 17–23 GB of ambient compressor. The constant's
own justification stopped holding.

The workload also shrank underneath it: the guarded job was Qwen3-Embedding-0.6B (14.32
GiB) when the figure was derived; after GH-81 it is BGE-small, ~7.5× smaller.

### What changed

`DEFAULT_MAX_COMPRESSOR_FRACTION` is **unchanged**. The issue explicitly forbids raising
it, and rightly — it would weaken the check for every guarded job including the
Qwen-class ones it was correctly derived for.

Crossing the ceiling is now a **suspicion requiring corroboration** by a signal only real
distress produces: swap in use above `SWAP_DISTRESS_BYTES` (1 GiB), or available memory
below the floor. A large compressor with neither has *absorbed* pressure successfully.
New `swap_used_bytes()` reads `sysctl -n vm.swapusage` and keeps `None` (unreadable)
distinct from `0` (positive evidence of no paging). The rule governs the mid-run check as
well as preflight, and **fails closed** when neither corroborating signal is readable.

Also fixed here: **#156's core fail-open**, which #157 names as its prerequisite. With
`total_memory_bytes() == 0` every ceiling is `None` and the watchdog disables itself, so a
run that "passed" only because the sysctl was blocked was indistinguishable from a
well-behaved one. `preflight()` now refuses with `EX_TEMPFAIL`. #156 stays open for its
remaining scope.

## 6. The defect that is still open, and why it matters

`_activity_repos` at `src/rebalance/ingest/index_ops.py:878` admits a repo on:

```sql
AND ( commits + pushes + prs_opened + prs_merged
    + issues_opened + issue_comments + reviews ) > 0
```

Authorship and participation count **equally**. One issue comment on a stranger's repo
auto-monitors it for 14 days. That is exactly how `deusdata/codebase-memory-mcp` got in —
its `github_activity` rows show every code column at zero and a single `issues_opened` or
`issue_comments`. The function's own docstring already says passive signals "must not
auto-monitor a repo"; the predicate is wider than the contract it documents.

#159 fixes **presentation**. #158 tweak #1 fixes **admission**. Both are needed: without
#158 the next such repo is still synced in full, still counted everywhere in the activity
layer outside the digest (`refresh_index` targets, `list_watched_repos`, `pulse.py:497`,
`next_actions.py:1121`), and still a **project-promotion candidate** —
`project_inference.py:914-941` draws its pool straight from `auto_discovered`.

The recommended split: authorship signals (`commits + pushes + prs_opened + prs_merged`)
auto-monitor; participation signals (`issues_opened + issue_comments + reviews`) do not,
or require operator confirmation. **Not authorized — offer it, do not just do it.**
